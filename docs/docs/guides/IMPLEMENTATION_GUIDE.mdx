# @flipova/foundation/web Implementation Guide

## Executive Summary

`@flipova/foundation/web` is a dedicated web-only entry point for the @flipova/foundation design system that ensures browser builds never accidentally include React Native dependencies. It provides a complete suite of UI components, design tokens, and utilities optimized for web environments.

**Key Features:**
- ✅ Automatic `.web.tsx` variant selection during build
- ✅ Pure browser build (no React Native packages)
- ✅ Full type safety with TypeScript declarations
- ✅ Optimized bundle with tree-shaking
- ✅ Seamless integration with web applications

---

## Architecture

### How .web.tsx Variant Resolution Works

The web build system uses a **three-phase resolution strategy** to ensure the correct platform-specific code is bundled:

#### Phase 1: Module Path Resolution (TypeScript)

When you import from `@flipova/foundation/web`:

```typescript
import { Button } from '@flipova/foundation/web';
```

TypeScript uses the path mapping from `tsconfig.json`:
```json
"@flipova/foundation/web": ["./foundation/web/index.ts"]
```

This resolves the import to the web barrel file: `foundation/web/index.ts`

#### Phase 2: Barrel File Resolution

The barrel file (`foundation/web/index.ts`) re-exports components from other foundation modules:

```typescript
// foundation/web/index.ts
export * from '../ui/components/Button';
export * from '../ui/components/Input';
export * from '../theme';
export * from '../tokens';
```

When importing `'../ui/components/Button'`, both `.web.tsx` and `.tsx` variants exist:
- `foundation/ui/components/Button.web.tsx` (web-specific)
- `foundation/ui/components/Button.tsx` (shared/fallback)

#### Phase 3: Extension Resolution Priority (tsup Build)

During the build process, tsup's web configuration applies the **extension priority chain**:

```typescript
esbuildOptions.resolveExtensions = [
  '.web.tsx',    // ← Web-specific TypeScript JSX (highest priority)
  '.web.ts',     // ← Web-specific TypeScript utilities
  '.tsx',        // ← Shared/fallback React component
  '.ts',         // ← Shared/fallback TypeScript
  '.jsx',        // ← Fallback JavaScript JSX
  '.js',         // ← Fallback JavaScript
  '.json'        // ← Configuration files (lowest priority)
];
```

**Result**: `foundation/ui/components/Button.web.tsx` is selected for the web bundle.

### Why Web Variants Are Necessary

React Native and web platforms have **fundamentally different APIs**:

| Aspect | React Native | Web |
|--------|-------------|-----|
| **Base Components** | `View`, `Text`, `ScrollView` | `div`, `span`, `html` (via React) |
| **Import Source** | `'react-native'` | `'react'` or `'react-dom'` |
| **CSS Styling** | StyleSheet object | CSS classes or inline styles |
| **Navigation** | React Navigation | React Router, Next.js |
| **HTTP Requests** | Fetch or native SDK | Fetch or axios |
| **File System** | Native APIs | Browser File API |

**Critical Issue**: If React Native imports accidentally reach a web bundle:
- React Native's `View` component will not work in the browser
- Native modules (e.g., camera, geolocation) will crash
- The application cannot run

**Solution**: The `.web.tsx` variants replace React Native implementations with equivalent browser implementations:

```typescript
// foundation/ui/components/Button.web.tsx (for web)
import React from 'react';
export const Button = ({ label, onPress }) => (
  <button onClick={onPress}>{label}</button>
);

// foundation/ui/components/Button.tsx (shared/fallback for React Native)
import React from 'react';
import { TouchableOpacity, Text } from 'react-native';
export const Button = ({ label, onPress }) => (
  <TouchableOpacity onPress={onPress}>
    <Text>{label}</Text>
  </TouchableOpacity>
);
```

## Web Build System

### Package Inclusion

**Included in web builds** (bundled):
- All components in `foundation/ui/components/`
- Theme system and tokens (`foundation/theme`, `foundation/tokens`)
- Design system configuration (`foundation/config`)
- Type definitions and utilities
- YAML-based configuration files

**Externalized from web builds** (not bundled, must be provided):
- `react`, `react-dom` (peer dependencies)
- All React Native packages (never needed in browser)
- Server-side packages: `express`, `ws`

### Native Packages Externalized

These packages are **explicitly externalized** to prevent them from leaking into web bundles:

**Expo Ecosystem:**
- `@expo/vector-icons` - Native icon system
- `expo-linear-gradient` - Native gradient rendering
- `expo-haptics` - Device vibration API
- `expo-camera`, `expo-image-picker` - Native file access
- `expo-video`, `expo-audio` - Native media playback

**React Native Core:**
- `react-native` - React Native runtime
- `react-native-gesture-handler` - Native gesture recognition
- `react-native-reanimated` - Native animations
- `react-native-safe-area-context` - Native safe area
- `react-native-screens` - Native navigation

**Icon & Animation Libraries (Native Variants):**
- `lucide-react-native` - Native icon implementation (web uses `lucide-react`)
- `lottie-react-native` - Native animation player (web uses `lottie-web`)
- `reanimated-color-picker` - Native color picker

### Output Structure

After build, the web bundle is in `dist/web/`:

```
dist/web/
├── index.d.ts              # TypeScript declarations
├── index.d.ts.map          # Source map for declarations
├── index.cjs               # CommonJS build
├── index.js                # ES module build
├── components.js
├── components.cjs
├── theme.js
├── theme.cjs
└── ...
```

**Two formats provided:**
- **CommonJS (.cjs)**: For Node.js and CommonJS bundlers
- **ES Modules (.js)**: For modern bundlers (Webpack, Vite, tsup)

## Integration Guide

### Setup for Web Applications

#### 1. Install @flipova/foundation

```bash
npm install @flipova/foundation
```

Or with your package manager:
```bash
yarn add @flipova/foundation
pnpm add @flipova/foundation
bun add @flipova/foundation
```

#### 2. Import from @flipova/foundation/web

**For web-only imports**, use the dedicated web entry point:

```typescript
// ✅ CORRECT: Web-only imports
import { Button, Input, Card } from '@flipova/foundation/web';
import { theme, tokens } from '@flipova/foundation/web';
```

**For cross-platform code** (Expo/React Native + Web):

```typescript
// ✅ CORRECT: Cross-platform imports (use platform-agnostic variants)
import { Button, Input } from '@flipova/foundation';
```

### Example: Using Components in a Web App

#### React Web Application

```typescript
import React, { useState } from 'react';
import { Button, Input, Card } from '@flipova/foundation/web';
import { theme } from '@flipova/foundation/web';

export default function LoginForm() {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');

  const handleLogin = () => {
    console.log('Login with:', { email, password });
  };

  return (
    <Card
      style={{
        padding: theme.spacing.lg,
        backgroundColor: theme.colors.surface,
        borderRadius: theme.radius.md,
      }}
    >
      <h1>Login</h1>
      
      <Input
        placeholder="Email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
      />
      
      <Input
        type="password"
        placeholder="Password"
        value={password}
        onChange={(e) => setPassword(e.target.value)}
      />
      
      <Button onPress={handleLogin}>
        Sign In
      </Button>
    </Card>
  );
}
```

#### Next.js Application

```typescript
// app/components/ProductCard.tsx

import { Card, Badge, Button } from '@flipova/foundation/web';

      <Badge variant="success">${product.price}</Badge>

        Add to Cart
      </Button>
    </Card>
  );
}
```

### Theme Integration

Access design tokens from the theme system:

```typescript
import { theme, tokens } from '@flipova/foundation/web';

// Using theme object
const buttonStyle = {
  backgroundColor: theme.colors.primary,
  padding: theme.spacing.md,
  borderRadius: theme.radius.lg,

// Using tokens for detailed control
const cardStyle = {
  padding: tokens.space[4],
```

## Troubleshooting

### Issue: "Cannot find module 'react-native'"

**Symptom**: Build error stating React Native is missing when using `@flipova/foundation/web`

**Root Cause**: Importing from the wrong entry point or using non-web variant code

**Solution**:
```typescript
// ❌ WRONG: Uses non-web variant which may have React Native code
import { Button } from '@flipova/foundation';

// ✅ CORRECT: Uses web-specific implementation
import { Button } from '@flipova/foundation/web';
```

### Issue: "Cannot find module 'expo'"

**Symptom**: Expo packages appear in web bundle despite using web entry point

**Root Cause**: Importing from a web file that re-exports a React Native-dependent module

**Solution**: Check `foundation/web/index.ts` to ensure it only re-exports web-safe modules. Verify that component implementations use `.web.tsx` variants.

### Issue: Bundle size larger than expected

**Symptom**: Web bundle includes unnecessary React Native code

**Root Cause**: tsup's externalization config might not be applied correctly

**Solution**: Verify `tsup.config.ts` includes all React Native packages in the `nativeExternal` array. Run build with verbose logging:
```bash
npm run build -- --verbose
```

### Issue: TypeScript errors with @flipova/foundation/web

**Symptom**: Type errors or missing exports when importing from web entry point

**Root Cause**: TypeScript declaration files may not be generated

**Solution**:
1. Ensure `declaration: true` in `tsconfig.json`
2. Rebuild: `npm run build`
3. Clear TypeScript cache: `rm -rf dist/ && npm run build`

### Issue: Component styles not applying

**Symptom**: UI components render but lack styling

**Root Cause**: CSS-in-JS or theme provider not properly configured

**Solution**: Ensure your app wraps components with the theme provider:
```typescript
import { ThemeProvider } from '@flipova/foundation/web';

export default function App() {
  return (
    <ThemeProvider>
      {/* Your app */}
    </ThemeProvider>
  );
}
```

## Build Configuration Details

### tsup Configuration for Web

The web build is defined in `tsup.config.ts`:

```typescript
{
  entry: { "web/index": "foundation/web/index.ts" },
  format: ["cjs", "esm"],
  esbuildOptions(options) {
    // Prioritize .web.tsx variants
    options.resolveExtensions = [
      '.web.tsx',
      '.web.ts',
      '.tsx',
      '.ts',
      '.jsx',
      '.js',
      '.json'
    ];
  }
}
```

### TypeScript Path Configuration

From `tsconfig.json`:

```json
{
  "paths": {
    "@flipova/foundation/web": ["./foundation/web/index.ts"]
  }
}
```

This tells TypeScript to resolve `@flipova/foundation/web` to the web barrel file.

## Best Practices

1. **Always use `@flipova/foundation/web` for web apps**: Ensures you get web-optimized code
2. **Use `@flipova/foundation` for cross-platform code**: When sharing between Expo and web
3. **Avoid importing `.native` files directly**: Use the automatic resolution instead
4. **Keep component API consistent**: Web and native variants should have the same interface
5. **Test both platforms**: Web and React Native versions may behave differently
